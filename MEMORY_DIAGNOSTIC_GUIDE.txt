WHAT TO LOOK FOR IN THE OUTPUT:
================================================================================

Pattern 1 - Memory grows continuously (NEVER decreases):
  [MEMORY] Initial: 50 MB
  [MEMORY] After queues: 150 MB (+100)
  [MEMORY] After Excel: 250 MB (+100)
  [MEMORY-T0] Batch 1: 280 MB (+30)  ← Should see this
  [MEMORY-T0] After map: 350 MB (+70)  ← PROBLEM: Growing!
  [MEMORY-T0] After write: 400 MB (+50)  ← Should see oscillation, not growth
  [MEMORY-T0] After GC: 300 MB (-100)  ← Good, GC is working
  Result: ❌ Queue is accumulating faster than consuming
  Fix: Reduce BATCH_SIZE to 100-150 or increase threads to 12-16

Pattern 2 - Memory spikes after mapping:
  [MEMORY-T0] Before mapping batch: 200 MB
  [MEMORY-T0] After mapping: 350 MB (+150)  ← PROBLEM: ColumnMapper doubles memory!
  [MEMORY-T0] After Excel write: 250 MB (-100)  ← Good
  [MEMORY-T0] After GC: 200 MB (-50)  ← Good
  Result: ❌ ColumnMapper creating too many copies
  Fix: Optimize ColumnMapper to stream instead of ArrayList

Pattern 3 - Memory doesn't drop after GC:
  [MEMORY-T0] After write: 400 MB
  [MEMORY-T0] After GC: 380 MB (-20)  ← PROBLEM: GC not effective!
  Result: ❌ True memory leak or fragmentation
  Fix: Check ThreadSafeExcelGenerator.writeBatch() for row accumulation

Pattern 4 - Excel write consumes unexpected memory:
  [MEMORY-T0] After map: 250 MB
  [MEMORY-T0] After Excel write: 500 MB (+250)  ← PROBLEM: POI buffering!
  Result: ❌ Apache POI caching rows in memory
  Fix: Force flush or use streaming mode

  5. Watch "Heap" graph in real-time
  6. Screenshot the graph when OutOfMemoryError occurs

What to look for:
  - Sawtooth pattern (good): Memory rises then drops sharply
  - Steady climb (bad): Memory keeps rising without drops
  - Vertical spike to red (crash): OutOfMemoryError imminent


================================================================================
CRITICAL QUESTIONS FOR DIAGNOSIS:
================================================================================

1. When does the OutOfMemoryError occur?
   - During parsing (reading file)?
   - During mapping (transforming records)?
   - During Excel writing (saving to file)?
   - After all complete (during cleanup)?

2. What batch number causes it?
   - If it's batch 1-5: Problem is initialization
   - If it's batch 10-20: Problem is queue buildup
   - If it's batch 50+ (near end): Problem is cumulative

3. How large is your production file?
   - Expected: 200 MB with 12,547 records
   - If larger: Need even smaller batch size

4. How many records does your file ACTUALLY have?
   - We assumed 12,547
   - If 50,000+ records: Batch size needs to be 50-100

5. Are you running other applications?
   - Chrome, IDE, Slack consume memory
   - They reduce available heap
