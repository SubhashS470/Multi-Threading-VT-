IF THE ISSUE PERSISTS:
================================================================================

ROOT CAUSE ANALYSIS (based on diagnostic output):

Scenario 1: "Memory grows steadily from 200 MB to 2000 MB by batch 15"
  → Cause: Batches accumulating in queue faster than consuming
  → Fix: 
      BATCH_SIZE = 250 → 100
      NUM_MAP_THREADS = 8 → 12
      Queue capacity: 5 → 3

Scenario 2: "Memory spikes 200 MB → 600 MB during ColumnMapper"
  → Cause: ColumnMapper creating too many ArrayList copies
  → Fix: 
      Stream the results instead of full ArrayList
      OR filter before mapping
      See COLUMN_MAPPER_OPTIMIZATION.txt for details

Scenario 3: "Memory drops after each batch, but peak is always at 1500+ MB"
  → Cause: Excel POI buffering too much data
  → Fix:
      Force flush every 10 batches: excelWriter.flushRows()
      OR use streaming XLSX format
      See EXCEL_OPTIMIZATION.txt for details

Scenario 4: "All looks good until final batch, then OutOfMemoryError"
  → Cause: Final cleanup or index rebuild consuming memory
  → Fix:
      Process in reverse: Write while parsing, then cleanup
      See FINAL_BATCH_OPTIMIZATION.txt for details
